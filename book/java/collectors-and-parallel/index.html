Collector 与并行流

用 Collector 把流收束成 Map、分组或字符串；并行流只有在对的场合才值得用。

13 分钟入门到进阶8 章手册
01

分组、计数与连接

Collectors.groupingBy 按分类函数把元素放进 Map，counting 统计数量，joining 把字符串连接起来。Collector 可以组合，但组合越多越要关注可读性。

02

并行流不是默认选项

parallelStream 会把工作拆给 ForkJoinPool。它适合数据量较大、操作无共享状态、计算成本高于调度成本的场景。小列表、I/O、阻塞调用和共享可变状态，往往会更慢或更危险。

并行流不会自动让代码线程安全；它只是改变执行方式。先用测量结果决定，而不是看到 Stream 就加 parallel。

03

避免在流里修改外部集合

下面这种写法在并行时会丢失数据，在串行时也只是看起来能工作：多个元素同时向同一个 ArrayList 添加。正确做法是用 collect，让 Collector 管理结果容器。

TAKEAWAYS

读完这一章

  • groupingBy / counting / joining 覆盖大多数聚合需求。
  • 并行流只适合无状态、计算密集、数据量足够的场景。
  • 不要在流中使用共享可变容器，交给 collect。
