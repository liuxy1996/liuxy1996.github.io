Rust / CHAPTER 09

测试、文档与发布

把边界写进测试，用 clippy 和 rustfmt 守住一致性，再用文档与示例说明公共接口。

11 分钟入门到进阶10 章手册
01

单元测试就在文件里

Rust 把测试当作语言的一部分。#[cfg(test)] 让测试模块只在测试构建时编译；#[test] 标记测试函数；assert_eq! 在失败时打印两边值。

02

把检查放进日常

cargo fmt 统一格式，cargo clippy 检查常见错误和风格问题，cargo test 跑测试，cargo doc 生成文档。能在本地一条命令完成的检查，不要留给上线后才发现。

03

注释解释设计，而不是重复代码

用 /// 写公共 API 文档，用 //! 写模块级说明。文档里的 Rust 代码块会被 cargo test 当作示例测试，这能防止文档与实现渐渐脱节。

内部注释更应该解释“为什么这样取舍”“这里有什么不变量”，而不是逐行翻译代码。

TAKEAWAYS

读完这一章

  • 测试写在同文件里，公共行为也要有集成测试。
  • 把 fmt、clippy、test 变成提交前的固定动作。
  • 文档注释应该记录接口契约与示例。
